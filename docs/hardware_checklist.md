# 实物上电验证清单

本清单用于在**真实硬件**上逐条核对 WindowsDuo-EthanMaven 的固件行为。

> **重要**：本仓库当前**尚未完成实物上电验证**。本清单是「待执行的验证步骤」，其中每一行的「预期现象」来自固件源码的设计值，
> **不是实测结果**。请逐条勾选并记录实测值；未勾选的条目一律视为未验证。

## 0. 准备

- [ ] 硬件：ESP32-WROOM-32E（Maker-ESP32）、MPU6050（0x68）、SSD1306 128×64（0x3C）、轻触按键、杜邦线、USB 数据线。
- [ ] 接线按 [README.md 第 3 节](../README.md#3-硬件清单与接线) 完成：SDA=GPIO23、SCL=GPIO22、按键=GPIO5+GND、VCC=3V3、共地。
- [ ] 开发环境按 [README.md 第 4 节](../README.md#4-arduino-ide-环境准备) 完成，固件已成功烧录（见第 5 节）。
- [ ] 串口监视器已打开，波特率 **115200**。
- [ ] 记录本次验证环境：开发板型号、库版本、操作系统（填在文末记录表）。

## 1. I2C 总线扫描

| 勾选 | 检查项 | 预期现象 | 不通过时的排查方向 |
| --- | --- | --- | --- |
| [ ] | 上电后 I2C 扫描 | 同时看到 **0x3C** 与 **0x68** 两个地址 | 只看到一个地址：检查另一个模块的 VCC/GND/SDA/SCL |
| [ ] | SSD1306 地址 | **0x3C**（个别模块为 0x3D） | 出现 0x3D 时需改固件中的 `SSD1306_ADDR` |
| [ ] | MPU6050 地址 | **0x68**（AD0 已接 GND） | 出现 0x69 说明 AD0 被拉高，请把 AD0 接 GND |
| [ ] | 总线速率 | 固件以 **400kHz** 初始化 I2C，通信稳定 | 线过长 / 上拉过弱时会出现随机读失败 |

## 3. 开机自动校准

| 勾选 | 检查项 | 预期现象 | 不通过时的排查方向 |
| --- | --- | --- | --- |
| [ ] | 上电后静止 **约 3 秒** | 自动完成一次零漂校准，`status` 由 `calibrating` 变为 `ok` | 一直停在 `calibrating`：设备未保持静止或传感器读数异常 |
| [ ] | 串口提示行 | 出现 `# calibration started: boot` 与 `# calibration done. ...` 两行 | 只有 started 没有 done：检查静止判定是否通过 |
| [ ] | 校准期间保持静止 | 校准被接受，串口给出零偏与基准俯仰角数值 | 若设备被移动，出现 `# calibration rejected: ...`，属**预期保护行为**，重新校准即可 |
| [ ] | 校准超时保护 | 持续抖动时最多约 8 秒后结束并保留旧零偏 | 超时属于保护逻辑，不是故障 |

## 4. 串口 JSON 输出

| 勾选 | 检查项 | 预期现象 | 不通过时的排查方向 |
| --- | --- | --- | --- |
| [ ] | 输出频率 | 每 **50ms** 一行，约 **20 行/秒** | 频率明显偏低：确认波特率是否为 115200 |
| [ ] | 行格式 | 每行一个完整 JSON 对象，以换行结束 | 出现断行/粘包：确认没有其他程序同时读串口 |
| [ ] | 字段完整性 | 每行含 `angle` / `status` / `mode` / `author` 四个字段 | 缺字段：确认库版本与固件是否匹配 |
| [ ] | `angle` | 数值在 **0.0 ~ 180.0** 之间，**保留一位小数** | 出现多位小数或超范围：记录原始行以便定位 |
| [ ] | `status` | 取值属于 `ok` / `calibrating` / `sensor_error` / `warming_up` | 出现其他字符串即为协议不符 |
| [ ] | `mode` | 取值属于 `default` / `calibrate` / `debug` | 同上 |
| [ ] | `author` | 恒为 `EthanMaven` | 固定值，不应变化 |
| [ ] | 示例行 | 形如 `{"angle":45.2,"status":"ok","mode":"default","author":"EthanMaven"}` | 字段顺序不保证，解析时请按字段名取值 |
| [ ] | 注释行 | 以 `#` 开头的提示行与 JSON 行混排 | PC 端解析必须跳过 `#` 行 |

## 5. 按键交互

| 勾选 | 检查项 | 预期现象 | 不通过时的排查方向 |
| --- | --- | --- | --- |
| [ ] | 短按（50~800ms） | 模式循环切换：`default` → `calibrate` → `debug` → `default` | 无反应：确认按键一端 GPIO5、另一端 GND |
| [ ] | 短按的串口提示 | 每次切换输出 `# mode switched to ...` | 无提示说明按键未被识别 |
| [ ] | OLED 模式短名 | 随模式变化显示 `STD` / `CAL` / `DBG` | 显示不变但串口变了：检查 OLED 刷新 |
| [ ] | 长按（≥ 800ms） | 立即触发一次**重新零漂校准**并进入 `calibrate` 模式 | 长按被识别为短按：确认按住时间确实超过 800ms |
| [ ] | 极短按下（< 50ms） | 被忽略，不切换模式 | 属预期行为 |
| [ ] | 按键抖动 | 30ms 软件消抖，不会一次按下触发多次切换 | 连跳多次：检查按键质量与走线 |
| [ ] | `debug` 模式计数 | JSON 中出现 `sp` / `lp`，短按/长按后计数增长 | 计数不增长说明按键事件未产生 |

## 6. 角度映射（0 ~ 180）

| 勾选 | 检查项 | 预期现象 | 不通过时的排查方向 |
| --- | --- | --- | --- |
| [ ] | 量程比例核对：合盖记 A、全开记 B，分别读串口 `angle`（长按校准后从 0 起读）；k = Δangle / Δ屏幕夹角 | k≈1.0 → 满量程可用；k<0.9 → 端点走不满，按 [README「机械安装前提」](../README.md#35-机械安装前提) 处理 | 用手机水平仪或量角器测屏幕与底座夹角，再与串口角度对比 |
| [ ] | 合盖端点 | 合到最小位置时 `angle` 接近 **0** | 端点不为 0：可长按重新校准零点 |
| [ ] | 展开端点 | 展开到最大位置时 `angle` 接近 **180** | 上限被限幅，超过部分不会继续增大 |
| [ ] | 单调性 | 缓慢开合过程中 `angle` **单调变化**，不跳变、不反向 | 反向：修改固件中的安装朝向矩阵（见 README 3.4） |
| [ ] | 平滑度 | 输出经低通处理，数值连续、无明显阶跃 | 抖动大：检查固定方式与桌面稳定性 |
| [ ] | 静止漂移 | 长时间静止后角度漂移在可接受范围内 | 漂移大：重新校准并确认无持续振动源 |
| [ ] | 反向倾倒 | 反方向倾倒时取绝对值方向，仍落在 0~180 内 | 属固件既定行为 |

> 实测建议：屏幕与底座的夹角用**手机水平仪或量角器**测量，再与同一姿态下串口输出的 `angle` 对比，即可算出 k；
> k 明显小于 1 时不要期望端点能走到 180，按 [README「机械安装前提」](../README.md#35-机械安装前提) 处理。
